# Локальный рабочий процесс OBS

> Английская версия: [README.md](README.md). При изменениях в документации
> локального OBS обновляйте и этот файл, чтобы версии оставались синхронными.

Этот пакет загружает презентацию с Яндекс.Диска, позволяет оператору
выбрать категорию и диапазон слайдов и записывает PNG-файлы в настроенную
локальную директорию OBS. Конвертация и операции с Яндекс.Диском разделяются
с ботом через `core`.

## Установка и запуск

На новом компьютере сначала получите актуальную локальную версию проекта из
ветки `main`, затем запустите установщик из клонированной копии:

```bash
git clone --branch main --single-branch \
  https://github.com/medianbc/pptx2png.git "$HOME/pptx2png"
cd "$HOME/pptx2png"
./install_obs_local.sh
```

Для другого каталога установки передайте путь установщику, например:

```bash
git clone --branch main --single-branch \
  https://github.com/medianbc/pptx2png.git "$HOME/my-pptx2png"
cd "$HOME/my-pptx2png"
./install_obs_local.sh "$HOME/my-pptx2png"
```

Установщик для Linux использует `apt-get`; он устанавливает Git, Python,
`venv` и LibreOffice Impress. Он создаёт виртуальное окружение `.venv`,
устанавливает зависимости, создаёт приватный `config.ini` для токена
Яндекс.Диска и генерирует запускающие скрипты для подготовки презентаций и
песен. Установщик сохраняет существующую конфигурацию и не обновляет уже
клонированный репозиторий.

### Установка на macOS

#### Требования

- macOS с установленным и доступным из Terminal Homebrew.
- Интернет-доступ к GitHub и репозиториям Homebrew/PyPI.
- Python 3.10 или новее. Установщик ставит Python через Homebrew; общая
  библиотека проекта объявляет `requires-python >= 3.10`.
- LibreOffice для преобразования PPT/PPTX в PDF и PNG. Установщик устанавливает
  приложение через Homebrew cask.

В репозитории не зафиксирована минимальная версия macOS. Workflow
`OBS macOS installation` в GitHub Actions устанавливает пакет на чистом
macOS runner и проверяет конвертацию. Установщик не содержит разветвлений по
Intel/Apple Silicon; дополнительно проверьте установку и конвертацию на целевой
машине.

#### Шаги установки

1. Установите Homebrew по инструкции на [brew.sh](https://brew.sh) и убедитесь,
   что команда `brew` доступна в Terminal:

   ```bash
   brew --version
   ```

2. Скачайте установщик и запустите его. Git для установки не требуется:

   ```bash
   curl -fL \
     https://raw.githubusercontent.com/medianbc/pptx2png/main/install_obs_local_macos.sh \
     -o "$HOME/install_obs_local_macos.sh"
   less "$HOME/install_obs_local_macos.sh"
   bash "$HOME/install_obs_local_macos.sh" "$HOME/pptx2png"
   cd "$HOME/pptx2png"
   ```

   Команда скачивает исходники ветки `main` архивом и распаковывает их в
   `$HOME/pptx2png`. Для другого каталога укажите его вместо этого пути.
   Установщик ставит Python и LibreOffice через Homebrew, создаёт `.venv`,
   устанавливает пакет `core` и зависимости локального приложения, а также
   создаёт `start_obs_local.sh` и `prepare_obs_songs.sh`. Для новой установки
   сам установщик не требует Git. Если запускаете установщик из уже
   имеющейся Git-копии, Git нужен только для проверки её origin. Повторный
   запуск в папке архивной установки использует уже распакованные файлы и не
   обновляет исходники автоматически.

3. Проверьте Python и наличие LibreOffice:

   ```bash
   ./.venv/bin/python --version
   test -x /Applications/LibreOffice.app/Contents/MacOS/soffice
   ```

   Если LibreOffice установлен в другом месте, проверьте, что команда
   `soffice` доступна в `PATH`.

4. Настройте `obs_local/settings.ini` и `config.ini`, как описано ниже.
   Интерактивная подготовка презентаций требует OAuth-токен Яндекс.Диска и
   значение `[YandexDisk] base_path`. Установщик может предложить сохранить
   токен; секретный файл создаётся с правами только для владельца.

5. Запустите нужный сценарий:

   ```bash
   ./start_obs_local.sh
   ```

Откроется меню: выберите `1` для подготовки презентации, `2` для подготовки
песен или `0` для выхода. Для прямого запуска подготовки песен с отладочными
логами (например, при диагностике) можно отдельно использовать:

```bash
./prepare_obs_songs.sh --debug
```

Из корня репозитория меню также запускается командой `python -m obs_local`.
Для прямого запуска сценариев остаются доступны `python -m
obs_local.run_obs_local` и `python -m obs_local.prepare_songs`.

## Конфигурация

- `obs_local/settings.ini` — не секретные параметры. В секции `[YandexDisk]`
  задаются `base_path` и `source_folder`, откуда локальный режим получает
  презентацию ближайшего воскресенья.
- В `[OBS Local paths]` задаются `root_path` и качество `standard`, `2k` или
  `4k`. Относительный `root_path` разрешается от корня репозитория.
- `[SlideCategories]` содержит слова для автоматического поиска категорий в
  заметках докладчика.
- В `[Song preparation]` настраиваются `program_url`, `local_zip_dir`,
  `local_pptx_dir`, пути поиска на Яндекс.Диске и флаг
  `cache_missing_yandex_song_zips`.
- Токен хранится отдельно в корневом `config.ini` в секции `[YandexDisk]`;
  для подготовки песен поддерживается `obs_local/config.ini` как fallback.
  Не размещайте токен в `settings.ini` и не коммитьте секретные файлы.

Пример секрета (вставьте собственный токен локально):

```ini
[YandexDisk]
token = ВАШ_OAUTH_ТОКЕН
```

### Текущая реализация

`python -m obs_local` (или `start_obs_local.sh`) открывает меню, в котором
можно выбрать подготовку презентации или песен. В сценарии презентации
программа получает с Яндекс.Диска материалы на ближайшее воскресенье,
показывает список и предлагает выбрать одну презентацию (`0`, `q` или
`cancel` отменяет выбор). После чтения заметок можно
обработать все слайды, выбрать найденную категорию или ввести один либо
несколько диапазонов вручную (например, `1-4, 7, 9-11`). Перед конвертацией
скрипт показывает диапазоны и каталог результата; можно подтвердить выбор,
вернуться к редактированию или отменить операцию. Итог сохраняется в
`root_path/ГГГГ-ММ-ДД/имя-презентации/идентификатор-запуска/категория`.
При первом запуске отсутствующие пути, качество и токен запрашиваются
интерактивно: обычные настройки сохраняются в `settings.ini`, токен — отдельно
в приватном `config.ini`.

Если папка служения или презентация на ближайшее воскресенье не найдена на
Яндекс.Диске, скрипт сообщит об этом и предложит повторить поиск (Enter),
указать путь к локальному файлу `.ppt`/`.pptx` или отменить подготовку
(ввести `esc` или `exit`). Отмена возвращает в главное меню, где можно
перейти к подготовке песен.

Выбор подготовки песен в меню запускает сценарий, который читает названия
песен из таблиц DOCX для выбранного воскресенья, ищет локальные PNG ZIP и PPTX,
затем — если
настроены удалённые пути и токен — ищет ZIP/PPTX на Яндекс.Диске. PPTX
конвертируются в PNG, результаты размещаются в отдельных нумерованных папках
в `root_path/Трансляция/Песни`; ненайденные песни помечаются. Результат
публикуется через staging-каталог, а предыдущая папка сохраняется как резервная
копия.

Для поиска через API Яндекс.Диска используются `yandex_zip_png_paths` и
`yandex_pptx_paths` вместе с OAuth-токеном. Настроенные URL общей папки не
заменяют эти пути и сейчас сами по себе не включают поиск. Ссылку на DOCX
программы задаёт `program_url`; если значение пустое, интерактивный сценарий
попросит ввести публичную ссылку на файл Яндекс.Диска и сохранит её в
`obs_local/settings.ini`. Если песня из программы не найдена, сценарий покажет
статус каждой песни и предложит ввести альтернативное название для повторного
поиска. Успешные альтернативные названия сохраняются локально в игнорируемом
Git-файле `obs_local/song_title_aliases.json` и применяются при следующих
запусках. Пустой ввод пропускает альтернативу. Для неинтерактивного запуска
по-прежнему можно передать `--program-file` или `--program-url`.

## Проверка подготовки песен для OBS

Отдельный тестовый скрипт читает таблицы песен для выбранного воскресенья из
настроенного DOCX, ищет подходящие файлы и подготавливает:

```text
<root_path>/Трансляция/Песни/01 - Song title/
```

Сначала проверяются локальные ZIP-файлы, затем локальные PPTX-файлы. После этого
при необходимости ищутся настроенные папки Яндекс.Диска: сначала ZIP, затем PPTX.
Папка всё равно создаётся и помечается `(не найдено)`, если подходящий материал
не найден. Приоритет отдаётся полному названию песни в имени файла; если такого
нет, может использоваться вариант, у которого совпадает хотя бы 75% слов названия.
Неоднозначные кандидаты не выбираются автоматически.

Настройте раздел `[Song preparation]` в `obs_local/settings.ini` и поместите локальные
файлы в `local_zip_dir` или `local_pptx_dir`. Чтобы протестировать локальный DOCX
вместо загрузки настроенной программы:

```bash
python -m obs_local.prepare_songs \
  --program-file ./path/to/meeting-program.docx \
  --date 2026-10-04
```

Чтобы использовать настроенный публичный URL документа Яндекс.Диска для ближайшего
воскресенья:

```bash
python -m obs_local.prepare_songs
```

Дополнительные удалённые папки поиска настраиваются как разделённые вертикальной
чертой пути Яндекс.Диска в `yandex_zip_png_paths` и `yandex_pptx_paths`. Для
удалённого поиска требуется токен `[YandexDisk]` в общем `config.ini` в корне
репозитория, который используется ботом. Токен из `obs_local/config.ini`
используется только как запасной вариант.
При публикации нового результата предыдущая папка `Трансляция/Песни`
сохраняется как резервная копия с временной меткой; автоматического удаления
резервных копий не происходит.

Когда используется подходящий локальный PPTX или удалённый ZIP/PPTX, его PNG-слайды
также сохраняются как ZIP в `local_zip_dir` (удалённые файлы сохраняют свою
относительную структуру папок). Чтобы просканировать все настроенные удалённые
папки ZIP и PPTX после обработки текущей программы и кэшировать файлы, у которых
ещё нет валидного локального PNG ZIP, установите `cache_missing_yandex_song_zips = true`
в секции `[Song preparation]`.
`yandex_zip_png_url` пока сохраняется как метаданные конфигурации, но не
используется для поиска через API. Для поиска используются настроенные пути
папок и OAuth-токен.

## Логи и устранение неполадок

Подготовка песен пишет ротирующие файлы логов `bot.log` (INFO и выше) и
`debug.log` (DEBUG и выше) в каталог, заданный в `[Logging] log_dir`.
По умолчанию на Linux это:

```text
/dev/shm/pptx2png_tasks/obs_local/logs/
```

На macOS при стандартном значении Linux в `settings.ini` используется каталог
`~/Library/Logs/pptx2png/obs_local/`. Пользовательское значение `[Logging]
log_dir` сохраняется; путь можно также переопределить аргументом `--log-dir`.

После неудачного запуска проверьте диагностический лог:

```bash
tail -n 100 /dev/shm/pptx2png_tasks/obs_local/logs/debug.log
```

Используйте `--debug`, чтобы также выводить DEBUG-сообщения в консоль, или
`--log-dir PATH`, чтобы выбрать другой каталог логов. Публичная ссылка на документ
и временный URL загрузки маскируются в диагностических сообщениях.
Настроенный `program_url` должен быть публичной ссылкой на файл с Яндекс.Диска в
формате `https://disk.yandex.ru/d/<public-key>` или
`https://disk.yandex.ru/i/<public-key>`. Ссылка вида
`https://docs.yandex.ru/view/d/<id>` открывает просмотрщик документа, но её ID
не является `public_key` API Яндекс.Диска; эти ID нельзя преобразовать друг в
друга. Используйте **Поделиться** на файле в Яндекс.Диске и скопируйте публичную
ссылку.
`curl -I -L`, возвращающий HTTP 200 для страницы просмотра, подтверждает, что
страница доступна, но не то, что файл доступен через публичный API ресурса
Диска. Ссылка `/i/` принимается как есть; загруженное содержимое проверяется,
чтобы убедиться, что это действительно DOCX-программа, а не изображение или HTML
CAPTCHA.

Изолированные тесты используют синтетические фикстуры DOCX/ZIP и не обращаются к
Яндекс.Диску:

```bash
python -m unittest obs_local.tests.test_prepare_songs -v
```
