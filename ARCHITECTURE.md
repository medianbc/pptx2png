# Архитектура PPTX2PNG

**Состояние документа:** актуальное
**Обновлено:** 03.10.2026

Подробные диалоги бота, варианты меню и ответы на пользовательские действия
описаны в [BOT_USER_FLOWS.md](./BOT_USER_FLOWS.md).

Документ описывает текущую структуру репозитория и реализованные сценарии.
Общий код конвертации и интеграции с Яндекс.Диском используется двумя
приложениями: Telegram-ботом и локальным интерактивным режимом для OBS.

## Назначение

Проект подготавливает презентации к показу:

- принимает PPT/PPTX, поддерживает обработку ZIP и ссылок в сценарии бота;
- конвертирует презентации в PNG, позволяет выбирать качество и диапазоны
  слайдов;
- поддерживает тёмный режим, извлечение заметок докладчика и проверку
  орфографии в боте;
- помогает найти презентацию на Яндекс.Диске и подготовить слайды
  для трансляции или локального каталога OBS.

```text
    ├── utils.py              # Общие утилиты, включая заметки докладчика
```

Некоторые модули в корне репозитория сохранены как тонкие compatibility-обёртки
для старых импортов. Основная реализация общего кода находится в
`core/pptx2png_core/`, а Telegram-кода — в `bot/`.
Локальный OBS-режим запускается из `obs_local/`; `updater.py` проверяет
официальную ветку проекта, обновляет Git- или архивную установку с
сохранением локальных данных и синхронизирует Python-зависимости.
Числовое меню локального режима включает редактирование настроек текущей ОС,
приватный ввод токена и подменю песен. Обновление библиотеки песен отдельно от
программы использует общий механизм кэширования PNG ZIP в `prepare_songs.py`.

```text
          │                               │
          └──────────────┬────────────────┘
                         ▼
            ┌──────────────────────────┐
            │ Shared Python package    │
            │ core/pptx2png_core/      │
            │                          │
            │ conversion, notes,       │
            │ Yandex Disk, structure   │
            └──────────────────────────┘
```

### Общий пакет `core`

`pptx2png-core` содержит функции, используемые обоими режимами: конвертацию
PPT/PPTX в PDF и PNG, обработку ZIP, извлечение заметок, определение диапазонов
по категориям, работу со структурой папок и API Яндекс.Диска. Telegram-специфичные
функции остаются в `bot/`.

### Telegram-бот `bot`

Бот запускается через `bot/__main__.py`; aiogram подключает обработчики обычной
конвертации и сценариев Яндекс.Диска. В обычном сценарии пользователь загружает
презентацию или ссылку, выбирает слайды и параметры обработки, после чего получает
результат. Команда `/sunday` запускает поиск презентаций на Яндекс.Диске,
подготовку выбранных категорий/диапазонов и загрузку результата обратно на Диск.

Фоновая задача `bot/folder_setup.py` создаёт дерево папок на ближайшее
воскресенье по `bot/template.yaml`: проверяет его при старте для пропущенного
запуска и каждый понедельник в полночь по локальному времени сервера,
повторяя неудачные попытки с интервалом из
`[FolderSetup] retry_interval_sec`. Базовая папка из настроек должна уже
существовать; она не создаётся автоматически.

Состояние незавершённых задач и Yandex-сессий хранится в памяти процесса. При
перезапуске такие сессии не восстанавливаются. `TaskLockManager`, блокировки
Yandex-сценариев и фоновая очистка задач защищают выполнение от повторной
обработки и оставшихся временных файлов.

### Локальный режим `obs_local`

`python -m obs_local` запускает интерактивный сценарий без Telegram:

1. Находит ближайшую дату служения и презентации в заданной папке Яндекс.Диска.
2. Предлагает оператору выбрать PPT/PPTX.
3. Извлекает заметки докладчика и предлагает диапазоны для категорий слайдов.
4. Конвертирует выбранный диапазон и записывает результат в настроенный
   локальный каталог.

Ручные диапазоны категорий сохраняются при переходах меню только в текущей
подготовке презентации. Режим `2` обрабатывает одну категорию, режим `4`
позволяет сначала настроить и выбрать несколько, затем конвертировать их
одним запуском движка в отдельные подпапки общего каталога запуска.

`obs_local/prepare_songs.py` отдельно готовит песни из DOCX-программы,
полученной по публичной ссылке Яндекс.Диска, экспортом Google Docs в DOCX
без Google-токена или из локального файла. `priority_cloud_disk` выбирает
`google`/`yandex` и соответствующую ссылку `program_google_url`/`program_yandex_url`.
Новые установки выбирают Google; старые без приоритета сохраняют источник
`program_url`. При пустой ссылке выбранного облака запрашивает и сохраняет её
только после успешного скачивания DOCX. При ошибке сразу предлагает повтор,
локальный DOCX или отмену, без перехода во второе облако. Показывает
результат поиска по каждой песне и позволяет повторить поиск по альтернативному
названию. Успешные альтернативы сохраняются локально в
`obs_local/song_title_aliases.json`. Общий для локальных сценариев
`obs_local/config_utils.py` обновляет INI-настройки с сохранением комментариев.
Главное меню: `1` — презентации, `2` — песни, `3` — настройки, `0`/Enter —
выход. В настройках доступны выбор облака, отдельные ссылки на программу,
скрытый ввод токена и проверка обновлений. Успешное обновление завершает меню
для перезапуска; отмена, ошибка или отсутствие новой версии возвращают в настройки.

## Запуск и установка

Из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ./core
python -m pip install -r bot/requirements.txt
python -m bot
```

Для локального режима установите пакет `core` и зависимости локального приложения:

```bash
python -m pip install -e ./core
python -m pip install -r obs_local/requirements.txt
python -m obs_local
```

Корневой `run_obs_local.py` и `python -m obs_local.run_obs_local` оставлены как
совместимые способы запуска. `manage.sh` предоставляет команды управления ботом
(в частности `start`, `stop`, `restart`, `status` и просмотр логов).

## Конфигурация и данные

- `bot/settings.ini` — несекретные настройки бота: пути, параметры Яндекс.Диска,
  таймауты и ключевые слова категорий.
- `bot/config.ini` — секреты бота и учётные данные интеграций. Если локального
  файла нет, бот поддерживает прежний корневой `config.ini`.
- `obs_local/settings.linux.ini`, `obs_local/settings.macos.ini`,
  `obs_local/settings.windows.ini` — независимые локальные настройки
  Яндекс.Диска, качества, каталогов вывода и логов; ОС выбирается автоматически.
  Файл текущей ОС создаётся при первом запуске из `obs_local/settings.ini`
  (шаблона/прежней конфигурации). Изменения сохраняются только в файл текущей ОС;
  локальные файлы игнорируются Git и сохраняются обновлятором.
  Логи OBS — `obs_local.log` и `debug.log`; обычная консоль показывает только
  предупреждения и ошибки, подробности включаются через `--debug`.
- `obs_local/config.ini` — токен Яндекс.Диска для локального режима; при
  отсутствии поддерживается прежний корневой `config.ini`.
- `user_settings.json` и списки доступа используются ботом для пользовательских
  настроек/доступа и не должны попадать в репозиторий.

Секреты хранятся отдельно от настроек и не коммитятся. Не переносите токены или
другие секретные значения в этот документ.

## Деплой

Workflow `.github/workflows/deploy.yml` запускается при push в ветки `test` и
`main` на self-hosted runner с меткой `raspberry`. Для `test` он синхронизирует
код в тестовую директорию, перезапускает бот и проверяет его статус; логи
сохраняются как GitHub Actions artifact. Для `main` workflow синхронизирует
код в production-директорию и перезапускает бот.

Конфигурационные файлы, списки доступа, пользовательские настройки и логи
исключены из синхронизации, чтобы деплой не перезаписывал локальные данные
окружения.

## Текущие ограничения

- Состояние активных задач хранится в памяти и теряется при перезапуске бота.
- Бот рассчитан на работу как один процесс; постоянное распределённое хранилище
  сессий и горизонтальное масштабирование не реализованы.
- Локальный режим является интерактивным CLI-сценарием, не отдельным web- или
  desktop-клиентом.
- Автоматические тесты находятся в `obs_local/tests` и `bot/tests`.
  Они используют синтетические данные и mock API; успешные тесты не заменяют
  отдельную проверку доступности пользовательских облачных документов.
