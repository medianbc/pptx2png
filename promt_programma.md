# Первый приоритет: песни из программы собрания для OBS

## Цель

Реализовать первый, упрощённый этап подготовки песенных слайдов для локального
режима OBS:

1. Получить актуальный документ программы собрания по одной постоянной ссылке.
2. Выбрать в документе блок программы, относящийся к целевому воскресенью.
3. Извлечь из этого блока только названия песен и их порядок.
4. Для каждой песни найти готовый ZIP или PPTX сначала в локальных папках,
   затем в настроенных папках Яндекс.Диска.
5. Создать в целевой папке OBS каталог каждой песни в порядке программы.
   Сохранить туда PNG из найденного ZIP либо PNG, полученные конвертацией PPTX.
   Если подходящий файл не найден, оставить каталог песни пустым.

На этом этапе **не** извлекать библейские тексты, не анализировать содержание
проповеди, не искать песни по текстам и не запускать автоматический watcher.
Эти функции остаются будущими отдельными этапами.

## Контекст текущего проекта

Проект разделён на общий пакет `core/pptx2png_core/`, Telegram-бот `bot/` и
локальное приложение `obs_local/`. Начинать с локального сценария и переиспользовать
общий код конвертации и Яндекс.Диска там, где он подходит.

До реализации изучить актуальные `ARCHITECTURE.md`, `README.md`,
`obs_local/app.py`, `obs_local/settings.ini` и `core/pptx2png_core/`.
Не предполагать, что существующий код уже умеет скачивать DOCX по публичной
ссылке или искать файлы по названию песни: подтвердить это в коде и документации
Яндекс.Диска.

## Конфигурация программы собрания

- Программа доступна по постоянной ссылке, которая задаётся один раз в
  `obs_local/settings.ini`, например:
  `https://docs.yandex.ru/view/d/GJamJ029JyWOsKXfRK5ZRSPegnqahzm72s0qoIz-cKg6SjhCN3pHZXhVQQ`
- Ссылка является настройкой, а не строкой, зашитой в код.
- Проверить поддерживаемый Яндексом способ получить содержимое документа по
  этой ссылке. Предпочесть официальный API Яндекс.Диска для публичного ресурса
  или иной документированный способ. Не парсить HTML viewer-страницы как
  основной способ, если API позволяет получить файл напрямую.
- Если для чтения публичного ресурса нужен токен, использовать локальный
  секрет из `obs_local/config.ini` или существующую конфигурацию Яндекс.Диска.
  Не помещать токен в ссылку, код, логи или репозиторий.
- Если документ невозможно скачать/прочитать по настроенной ссылке, завершить
  операцию с понятной диагностикой. Не искать молча другую программу или старую
  локальную копию.
- На первом этапе поддержать DOCX. Не добавлять поддержку других форматов
  программы без отдельного решения.

## Выбор даты и блока программы

- При ручном запуске поддержать параметр даты `YYYY-MM-DD`; без него вычислять
  ближайшее целевое воскресенье согласно часовому поясу и правилам, принятым
  в `obs_local`. Перед обработкой показывать выбранную дату.
- В документе искать заголовок программы по смысловому шаблону
  `Программа собрания на <дата>`, допускающему вариации пробелов, регистра,
  необязательного `г.` и разделителей даты. Пример:
  `Программа собрания на 04.10.2026 г.`
- Сопоставлять дату заголовка с целевой датой точно. Не выбирать соседнюю
  архивную дату, не извлекать песни из шаблона с `??.??.2026` и не использовать
  прошлую программу как fallback.
- Рассматривать содержимое от заголовка с целевой датой до следующего заголовка
  программы, явной границы архивной/шаблонной секции или конца документа.
- Если дата не найдена, встречается несколько заполненных блоков с той же
  датой либо границы блока неоднозначны — остановить обработку песен и сообщить
  об этом. Не выбирать кандидата молча.

## Извлечение песен

- Читать DOCX в исходном порядке, сохраняя порядок абзацев и таблиц. Нельзя
  извлекать сначала весь текст, а потом таблицы: это теряет позицию таблиц
  относительно блоков собрания.
- Искать таблицы песен внутри уже выбранного блока даты. Узнавать их по строке
  заголовка, содержащей колонку `название песни` (допускать различия регистра
  и пробелов).
- Из строки заголовка определить колонку названия по её подписи. Не полагаться
  на жёсткий номер колонки.
- Для каждой строки данных брать только значение из колонки `название песни`.
  Полностью игнорировать колонку `п.` (в том числе её нумерацию) и колонку
  `кто говорит (вступление, молитва)` независимо от того, заполнена она или нет.
- Порядок песен определять только порядком строк и таблиц в документе.
  Порядковые номера для выходных каталогов назначать заново с `01`, `02`, ...
  Не пытаться сортировать или нумеровать песни по значениям исходного столбца
  `п.`: эти значения могут пропускаться или продолжаться между таблицами.
- Удалять пробелы по краям и игнорировать пустые строки/заголовки/значения,
  состоящие только из `?`. Сохранять исходное написание названия песни,
  нормализуя только имя каталога для безопасной файловой системы.
- Не извлекать названия песен из основного текста абзацев, объявлений или
  дополнительных заметок — только из подходящих таблиц внутри целевого блока.
- Если целевой блок найден, но таблиц песен нет или все строки пусты, явно
  сообщить об этом; не брать список из архива или шаблона.

## Поиск аудио-визуальных материалов

Для каждого названия песни искать материалы строго в следующем порядке.
Переходить к следующему источнику/формату только при отсутствии подходящего
результата на предыдущем шаге:

1. ZIP в настроенной локальной папке ZIP.
2. PPTX в настроенной локальной папке PPTX.
3. ZIP в настроенных папках Яндекс.Диска.
4. PPTX в настроенных папках Яндекс.Диска.

### Настраиваемые каталоги

Добавить параметры в `obs_local/settings.ini` для:

- локальной папки ZIP-архивов песен;
- локальной папки PPTX песен;
- одной или нескольких папок Яндекс.Диска для ZIP;
- одной или нескольких папок Яндекс.Диска для PPTX;
- корня данных OBS (уже задаётся `OBS Local paths.root_path`).

Папки Яндекс.Диска должны быть явно заданы; не сканировать весь Диск. Если
конфигурация нескольких папок усложняет первую версию, начать с одной
настраиваемой папки на тип файла и расширить позже.

### Сопоставление файлов с названием песни

- Сначала искать по имени файла, содержащему название песни. Сравнение
  нечувствительно к регистру; разрешить безопасную нормализацию пробелов,
  подчёркиваний и дефисов.
- Не использовать fuzzy-сходство, которое может выбрать другую песню.
  Нечёткое или неоднозначное совпадение показывать как не найденное/
  требующее ручной проверки, а не брать автоматически.
- Если найдено несколько равноценных файлов одного типа в одном источнике,
  не выбирать произвольный. Сообщить о неоднозначности и оставить каталог песни
  без автоматически выбранных PNG.
- При наличии совпадения на более приоритетном шаге не перезаписывать его
  результат файлом из следующего источника.
- Если подходящего ZIP нет, проверить локальный PPTX, затем Яндекс.Диск в
  описанном порядке. Не скачивать удалённый файл до определения, что локального
  приоритетного варианта нет.

### Обработка ZIP

- Считать ZIP песенным материалом, содержащим готовые PNG.
- Распаковывать во временную папку, проверять пути записей архива и принимать
  только обычные PNG-файлы. Не допускать path traversal, записи за пределы
  временной папки или извлечения исполняемых файлов.
- Сохранять PNG в порядке имён файлов с естественной сортировкой
  (`slide_2.png` перед `slide_10.png`), если порядок не задан иначе.
- Если ZIP повреждён или внутри нет PNG, зарегистрировать ошибку и перейти к
  следующему источнику по установленному приоритету, не считать такой архив
  успешным совпадением.
- Не считать ZIP с вложенным PPTX подходящим на этом этапе, если поддержка
  такого формата специально не добавлена и не протестирована.

### Обработка PPTX

- Скачивать найденный PPTX во временную папку, если он находится на Яндекс.Диске.
- Конвертировать все слайды существующим общим конвертером из
  `core/pptx2png_core/converter_engine.py`; использовать настроенное качество
  OBS, если оно применимо.
- Сохранять полученные PNG в целевую папку песни в порядке слайдов.
- Ошибка конвертации конкретного файла должна быть явной. Не сообщать об успехе
  и не оставлять частичный результат без предупреждения.
- Временные файлы удалять после завершения; итоговые PNG сохранять только
  в предназначенной выходной папке OBS.

## Выходная структура

Для выбранной программы создать структуру:

```text
<OBS Local paths.root_path>/
└── Трансляция/
    └── Песни/
        ├── 01 - Славен Господь/
        │   ├── slide_1.png
        │   └── slide_2.png
        ├── 02 - Бог всего творения/
        │   └── ...
        └── 03 - Вижу я рассвет/
            └── (пусто, если материал не найден)
```

- Номер (`01`, `02`, ...) соответствует порядку найденной песни в целевой
  программе, а не нумерации в колонке `п.`.
- Название после номера сохранять читаемым; очищать запрещённые/небезопасные
  символы пути и ограничивать длину компонента имени.
- Создавать каталог для каждой найденной песни до поиска/обработки материала.
  Если ни ZIP, ни PPTX не найден, оставить каталог пустым и включить песню
  в итоговый отчёт как `материал не найден`.
- Выходной путь должен оставаться стабильным, как в примере; не добавлять к нему
  дату или случайный `run_id`, иначе OBS потеряет настроенную папку.
- Собирать новый результат сначала во временной staging-папке рядом с целевой.
  После успешной обработки всех песен публиковать его в
  `<root_path>/Трансляция/Песни`. Если целевая папка уже существует, не удалять
  её безвозвратно: сохранить предыдущий результат как резервную копию и
  сообщить её путь. При неудаче публикации восстановить предыдущий результат.
  Автоматически удалять резервные копии на первом этапе нельзя.
- Не изменять и не удалять файлы за пределами управляемой приложением папки
  `Трансляция/Песни`.
- Не создавать каталоги для неопознанных/пустых названий.

## Пользовательский сценарий

1. Пользователь запускает локальную подготовку для ближайшего воскресенья или
   передаёт дату явно.
2. Приложение показывает дату и получает DOCX по настроенной постоянной ссылке.
3. Приложение находит блок с точным заголовком этой даты и выводит извлечённый
   список песен в порядке документа.
4. Приложение ищет и обрабатывает материалы по приоритету локальные ZIP →
   локальные PPTX → Яндекс.Диск ZIP → Яндекс.Диск PPTX.
5. Для каждой песни создаётся целевая папка. Если материалы не нашлись —
   папка остаётся пустой.
6. В конце выводится отчёт: дата, список песен и порядковые номера, источник
   каждого успешного результата, количество PNG и список песен без материалов
   или с ошибкой.

## Тестирование

Автоматическое тестирование обязательно. Использовать обезличенную DOCX-фикстуру
по структуре образца и мок Яндекс.Диска. Обычные тесты не должны обращаться
к реальной постоянной ссылке, Яндекс.Диску, OBS или Telegram.

Минимальные тесты:

1. Из блока 04.10.2026 извлекаются только названия песен и в порядке таблиц
   документа; колонки `п.` и говорящего игнорируются.
2. Нумерация песен в таблицах может иметь пропуски/продолжаться между таблицами;
   имена выходных каталогов всё равно получают последовательные `01`, `02`, ...
3. Блоки архива с датами 27.09, 20.09, 13.09 и 06.09, памятка и шаблоны не
   включаются в результат для 04.10.
4. Вариации пробелов, регистра и необязательного `г.` в заголовке даты
   поддерживаются; другая дата не подходит.
5. Плейсхолдеры, пустые названия и текст вне таблиц песен игнорируются.
6. Проверяется приоритет источников: локальный ZIP → локальный PPTX →
   Яндекс.Диск ZIP → Яндекс.Диск PPTX.
7. При отсутствии файлов всех типов целевая папка создаётся пустой.
8. Неоднозначное имя файла, повреждённый ZIP, ZIP без PNG, ошибки загрузки
   и конвертации дают явный статус и не фиктивный успех.
9. ZIP с попыткой path traversal не может записать файлы за пределы временного
   каталога.
10. Существующая выходная папка не удаляется/не перезаписывается без выбранной
    и протестированной стратегии; при публикации предыдущая версия сохраняется
    и восстанавливается, если замена завершилась ошибкой.

## Критерии готовности первого приоритета

- Одна постоянная ссылка на DOCX задаётся конфигурацией и используется для
  получения программы; невозможность её чтения диагностируется явно.
- Для заданной даты выбирается только точный блок воскресной программы.
- Из блока извлекаются только названия песен из таблиц, в порядке документа.
- Для каждой песни поиск выполняется в согласованном приоритете четырёх
  источников/типов.
- PNG из ZIP или конвертированного PPTX попадают в каталог соответствующей
  песни в целевой структуре OBS.
- Для песни без найденного материала остаётся созданная пустая папка.
- Исходные DOCX, ZIP и PPTX не изменяются; существующий результат не удаляется
  молча.
- Есть автоматические тесты на парсер, приоритет поиска, ошибки и пустые папки.
- Обработка библейских текстов и автоматизация бота не включены в этот этап.
