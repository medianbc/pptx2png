Краткое назначение продукта

Telegram-бот для автоматизации подготовки презентаций к церковным трансляциям. Решает три задачи:

  1. Конвертация PPTX/PPT/ZIP в PNG — с выбором качества (Standard/2K/4K), dark mode (чёрный фон, белый текст), упаковкой в ZIP.
  2. Подготовка трансляций с Яндекс.Диска — автоматический поиск презентаций на ближайшее воскресенье, извлечение заметок докладчика, определение слайдов проповеди, раскладка по структуре папок.
  3. Проверка орфографии — через API Яндекс.Спеллера перед конвертацией.

2.5. Модель данных

Хранилище в памяти (sessions):

  • Обычные конвертации: task_<chat>_<user>_<msg>_<hex>
  • Yandex picker-сессии: yd_<user>_<chat>
  • Yandex-задачи: yd_task_<user>_<hex>

Активные сессии (для блокировок):

  • yd_active_sessions: Dict[str, str] — {user:chat → nonce}
  • yd_active_tasks: Set[str] — {task_id}

Настройки пользователей — user_settings.json.

3. Клиентская часть

Клиент — Telegram. Отдельных web/mobile/desktop приложений нет.

3.1. Платформы

Telegram Android, iOS, Desktop, Web — все платформы работают.

3.2. Реализованные сценарии

Обычная конвертация:

  1. /start — приветствие + настройки
  2. Загрузка .pptx/.zip/ссылки → кнопки «Все слайды / Выбрать слайды»
  3. Выбор диапазона слайдов
  4. Проверка орфографии (опционально)
  5. Конвертация → отправка ZIP + PDF

Yandex-трансляция (/sunday):

  1. Проверка Яндекс.Диска
  2. Поиск папки ближайшего воскресенья
  3. Список pptx с размерами
  4. Выбор файла
  5. Download + конвертация + извлечение заметок
  6. Промпт подтверждения:
    • Если проповедь найдена → 3 кнопки (Confirm / Edit / Skip)
    • Если не найдена → 2 кнопки (Edit / Skip) + причина
  7. Ручной ввод диапазона при необходимости
  8. Upload ZIP:
    • Проповедь → проповедь - png/<file>_проповедь.zip
    • Остальные → pptx2png/<file>/<file>_слайды.zip
  9. Отчёт с ссылками на папки

3.3. Взаимодействие с сервером

  • Аутентификация: whitelist + одобрение админа
  • Обработка ошибок: _safe_edit логирует, пользователю понятные сообщения
  • Состояние: только на сервере в sessions

5. Приложения

5.1. Схема работы /sunday

Пользователь → /sunday ↓ Bot: проверка Yandex client ↓ Bot: resolve_sunday_paths (месяц → дата → Служение/Трансляция) ↓ Bot: find_pptx_in_source ↓ Bot → Пользователь: список pptx + кнопки [🎯/📄 file, 📁 Все, ❌ Отмена] ↓ Пользователь → yd_pick (например, все файлы) ↓ Bot: _yd_prepare_files (task_dir в /dev/shm) ├─ для каждого файла: │ ├─ download_file │ ├─ convert_all_pngs (PPTX → PNG) │ ├─ extract_speaker_notes │ └─ find_sermon_range ↓ Bot: needs_confirm? ├─ ДА → _yd_render_sermon_prompt │ ├─ matches ≥2 → 3 кнопки (Confirm/Edit/Skip) │ └─ matches <2 → 2 кнопки (Edit/Skip) │ ↓ │ Пользователь → ok/skip/edit │ ↓ │ _yd_upload_files │ └─ НЕТ → _yd_upload_files _yd_upload_files: ├─ zip_tmp_dir = mkdtemp() в /tmp ├─ для каждого файла: │ ├─ ensure_folder(pptx2png/) │ ├─ split PNG: sermon / others │ ├─ create_zip_stream(sermon_pngs) → /tmp/*_проповедь.zip │ ├─ upload → sermon_dir/ │ ├─ create_zip_stream(other_pngs) → /tmp/*_слайды.zip │ └─ upload → pptx2png_dir/ ├─ send_report (со ссылками) └─ cleanup (task_dir, zip_tmp_dir, sessions)

6. Резюме

Проект в рабочем состоянии. Основной функционал — конвертация, /sunday, определение проповеди, ZIP-загрузка на Диск — работает стабильно. Критических багов, ломающих основной flow, нет.

Что закрыть в следующей итерации

  1. High Удалить reply-проверку в handle_text_input — ломает обычную конвертацию.
  2. High Добавить валидацию timeout в bot.py — при ≤ 0 бот не должен запускаться.
  3. Medium Добавить автотесты — smoke-test для create_zip_stream, _format_ranges_text, resolve_sunday_paths (mock).
  4. Medium Ускорить upload — параллельная загрузка или chunked PUT.

Что отложено на будущее

  • Multi-tenancy (несколько Yandex-аккаунтов).
  • Метрики / алертинг.
  • Web-интерфейс для админа.
  • Расширение форматов (ODT, DOCX).
