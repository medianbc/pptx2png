# PPTX2PNG Bot — Release Notes v1.3

**Дата:** 19 сентября 2026
**Статус:** Подготовлено к деплою (test → main)
**Тип релиза:** Feature release + Reliability improvements

---

## 📌 Краткое описание (TL;DR)

Добавлена интеграция с **Яндекс.Диском** для автоматической подготовки материалов воскресных трансляций. Бот находит презентации в структуре папок церковного Диска, конвертирует их в PNG и раскладывает по папкам трансляции. Реализован полный цикл: от поиска файла до выгрузки результата с автоматическим определением проповеди по заметкам докладчика.

**Ключевые нововведения:**
- Интеграция с Яндекс.Диском (авторизация, чтение, запись)
- Команда `/sunday` — подготовка трансляции в один клик
- Работа с древовидной структурой папок через `template.yaml`
- Автоматическое определение диапазона проповеди по speaker notes
- Диалог подтверждения для неоднозначных случаев
- Устойчивость к дублирующим callback-ам, гонкам сессий, ошибкам сети
- Разбивка больших отчётов на несколько сообщений

## 📖 Подробное описание

### 1. Новый функционал

#### 1.1. Интеграция с Яндекс.Диском

Бот получил встроенный **асинхронный клиент** для работы с REST API Яндекс.Диска.

**Что это даёт пользователю:**

| Возможность | Описание |
|-------------|----------|
| **Проверка доступа** | При `/start` бот проверяет доступность Диска и сообщает статус |
| **Чтение структуры** | Бот видит все папки и файлы в настроенной базовой директории |
| **Скачивание** | Потоковая загрузка файлов без переполнения памяти |
| **Создание папок** | Автоматическое создание недостающих папок по шаблону |
| **Загрузка** | Отправка PNG-слайдов на Диск с перезаписью существующих |

**Конфигурация:**
- Токен хранится отдельно в `config.ini` (не коммитится)
- Параметры структуры — в `settings.ini` (публичный)
- Структура папок — в `template.yaml` (публичный)

#### 1.2. Команда `/sunday`

Главное нововведение — команда для автоматизированной подготовки трансляции.

**Алгоритм работы:**

1. **Определение даты** — бот вычисляет **ближайшее предстоящее воскресенье**.
2. **Разрешение пути** — находит папки:
   ```
   {base_path}/{MM МЕСЯЦ YYYY}/{DD.MM.YYYY}/Служение/
   ```
3. **Поиск pptx** — находит все презентации с датой воскресенья в имени.
4. **Показ выбора** — если файлов несколько, предлагает кнопки:
   - 🎯 `Служение DD.MM.YY.pptx` (приоритетный, со словом «служение»)
   - 📄 `Объявления DD.MM.YY.pptx`
   - 📁 **Все подряд** — обработать все файлы за один раз
   - ❌ **Отмена**
5. **Обработка** — скачивание, конвертация, раскладка, загрузка.
6. **Отчёт** — количество загруженных PNG с деталями по каждому файлу.

#### 1.3. Автоматическое определение проповеди

Бот анализирует **заметки докладчика** (speaker notes) в презентации и ищет в них ключевое слово (по умолчанию «проповед»).

**Как это работает для пользователя:**

- **Найдено ≥2 совпадения** — бот показывает найденные слайды и предлагает диапазон:
  ```
  🎯 Найдена пометка «проповедь»
  📄 Файл: Служение 20.09.26.pptx
  📌 Слайды с пометкой: 5, 6, 7, 20, 21, 22
  📊 Предлагаемый диапазон: 5–22

  [✅ Подтвердить] [✏️ Изменить] [⏭ Пропустить]
  ```
- **Найдено 1 совпадение** — считается ненадёжным, все слайды идут в общую папку.
- **Не найдено** — всё уходит в общую папку без диалога.
- **Заметки прочитались частично** — проповедь не определяется автоматически.

#### 1.4. Раскладка результатов

**Структура на Яндекс.Диске после обработки:**
```
{дата}/
├── Служение/                          ← исходные pptx (не трогаются)
└── Трансляция/
    ├── Гимны - png/                   ← создано из template.yaml
    ├── Молитва/                       ← создано из template.yaml
    ├── проповедь - png/               ← слайды проповеди
    │   └── {имя_файла}_slide_NN.png   ← с префиксом имени файла
    └── pptx2png/
        └── {имя_файла}/               ← остальные слайды
            └── slide_NN.png
```

**Ключевые особенности:**
- **Проповедь** — всегда в общую папку `проповедь - png/` с префиксом имени исходного файла (защита от перезаписи при обработке нескольких pptx).
- **Остальные слайды** — каждый файл в **свою подпапку** внутри `pptx2png/`.
- **Шаблонные папки** (`Гимны`, `Молитва` и т.д.) — создаются пустыми для удобства ручной доработки.

### 2. Изменения пользовательского опыта

#### 2.1. Что стало удобнее

| Было | Стало |
|------|-------|
| Нужно вручную выгружать pptx в чат | `/sunday` — одна команда |
| Файлы разложены вручную по папкам | Автоматическая раскладка |
| Не было шаблона структуры | `template.yaml` создаёт всё сам |
| Проповедь искали вручную | Автоопределение по заметкам |
| Не было защиты от двойных кликов | Все кнопки блокируются после нажатия |
| При ошибке — непонятный traceback | Понятные сообщения на русском |

#### 2.2. Обратная связь

Бот теперь **постоянно сообщает о статусе**:
- Проверка Диска → ✅/❌
- Поиск структуры → 📁
- Скачивание → 📥
- Конвертация → ⚙️
- Загрузка → 📤
- Отчёт с деталями по каждому файлу

#### 2.3. Диалог с подтверждениями

При обнаружении проповеди бот **не действует молча**, а показывает:
- Список найденных слайдов с пометкой.
- Предлагаемый диапазон.
- Кнопки **Подтвердить / Изменить / Пропустить**.

Это снижает риск неверной раскладки, если ключевое слово встретилось в неожиданном месте.

#### 2.4. Ручной ввод диапазона

При выборе **✏️ Изменить** бот ждёт текстового ввода:
```
✏️ Введите диапазон проповеди
📄 Файл: Служение 20.09.26.pptx
📊 Всего слайдов: 42

Пример: 5-30 или 5,7,10-15
```
- Поддерживаются **диапазоны** (`5-30`), **отдельные номера** (`5,7,10`), **смешанный формат**.
- Если введённый диапазон превышает реальное число слайдов — обрезается с предупреждением.
- Если начальный слайд не существует — проповедь пропускается.

#### 2.5. Устойчивость к ошибкам

- **Двойные клики** — второй клик получает «⏳ Идёт обработка».
- **Устаревшие кнопки** — старые cancel-кнопки не срабатывают на новых сессиях.
- **Сетевые ошибки** — пользователь видит осмысленное сообщение, а не traceback.
- **Отмена во время обработки** — сессия корректно снимается.
- **Большие отчёты** — разбиваются на несколько сообщений при превышении лимита Telegram.

### 4. Технические улучшения (для администратора)

#### 4.1. Архитектура

- **Разделение конфигурации:**
  - `config.ini` — секреты (токен бота, токен Яндекс.Диска, ID админа)
  - `settings.ini` — публичные параметры (пути, имена папок, keyword)
  - `template.yaml` — структура папок
- **Модульность:**
  - `yandex_disk.py` — клиент API (потоковый download, разбор ошибок, пагинация)
  - `structure.py` — работа с `template.yaml` (валидация, рекурсивное создание)
  - `sermon_detector.py` — поиск диапазона проповеди
  - `utils.py` — извлечение текста и заметок из pptx

#### 4.2. Надёжность

- **Потоковая загрузка/выгрузка** — без буферизации всего файла в памяти.
- **Разбор ошибок 409** при создании папок — не считаем «уже существует» успехом, если это конфликт имени.
- **Защита от рекурсивных `template.yaml`** через YAML-anchors.
- **Защита от пустого `sermon_keyword`** — fallback на значение по умолчанию.
- **Общая `aiohttp.ClientSession`** для всех запросов — экономия TCP-соединений.
- **Проверка результатов `ensure_folder`** — не пытаемся загрузить в несуществующую папку.
- **Nonce-защита сессий** — старые callback-и не влияют на новые сессии.

#### 4.3. Очистка ресурсов

- **Локальные временные папки** удаляются гарантированно через `try/finally`.
- **Старые задачи** удаляются по возрасту (2 часа) фоновым процессом.
- **`touch_task`** обновляет mtime при каждом взаимодействии — активные задачи не удаляются.

### 6. Что нужно для работы

**Минимальные требования:**

1. **Токен Яндекс.Диска** — получить на [oauth.yandex.ru](https://oauth.yandex.ru/).
2. **`config.ini`** — добавить секцию `[YandexDisk]` с полем `token`.
3. **`settings.ini`** — задать:
   - `base_path` — путь до папки с презентациями.
   - `source_folder`, `target_folder` — имена подпапок.
   - `sermon_keyword` — ключевое слово для поиска проповеди.
4. **`template.yaml`** — определить структуру папок трансляции.
5. **`pyyaml`** — установлен в виртуальном окружении.
6. **`requirements.txt`** — обновлён с зависимостями.

**Без токена Яндекс.Диска:**
- Бот запускается, но `/sunday` недоступна.
- Все остальные команды работают.

### 7. Известные ограничения

| Ограничение                                     | Обход                             |
|-------------------------------------------------|-----------------------------------|
| Обработка только `.pptx`/`.ppt`                 | ZIP с pptx внутри поддерживается  |
| Заметки читаются только из `python-pptx`        | Для `.ppt` конвертируем в `.pptx` |
| Лимит Telegram 4096 символов                    | Отчёт разбивается на части        |
| 2 одновременных конвертации                     | `converter_semaphore = 2`         |
| Лимит файла 45 МБ на архив                      | Проверка до отправки              |

### 8. Миграция с предыдущей версии

**Что делать при обновлении:**

1. **Обновить `config.ini`** — добавить `[YandexDisk]` с токеном.
2. **Обновить `settings.ini`** — добавить секцию `[YandexDisk]`.
3. **Создать `template.yaml`** в корне проекта.
4. **Обновить зависимости** — `pip install pyyaml` (уже установлено).
5. **Перезапустить бота** — `./manage.sh restart`.

**Обратная совместимость:**
- Если `token` не указан — бот работает в старом режиме.
- Все старые функции не затронуты.
- Старые сессии не конфликтуют с новыми (используются разные ключи).
