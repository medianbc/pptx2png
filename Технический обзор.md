## 1. Инфраструктура  
  
### 1.1. Аппаратная платформа  
  
| Компонент | Характеристика |  
|-----------|---------------|  
| **Устройство** | Raspberry Pi |  
| **Хранилище** | SD-карта (ограниченный ресурс записи) |  
| **RAM-диск** | `/dev/shm` (временное хранилище в оперативной памяти) |  
| **ОС** | Linux (Raspberry Pi OS) |  
  
### 1.2. Особенности /dev/shm  
  
```  
┌─────────────────────────────────────────────────────────────────────────────┐  
│                          /dev/shm (RAM-диск)                               │  
├─────────────────────────────────────────────────────────────────────────────┤  
│                                                                             │  
│  ⚡ Преимущества:                                                           │  
│  • Максимальная скорость (оперативная память)                              │  
│  • Отсутствие износа SD-карты (критично для Raspberry Pi)                  │  
│  • Автоматическая очистка при перезагрузке                                 │  
│                                                                             │  
│  ⚠️ Особенности:                                                            │  
│  • Данные НЕ сохраняются при перезагрузке                                  │  
│  • При сбое питания — все данные теряются                                  │  
│  • Ограниченный размер (обычно 50% от RAM)                                 │  
│  • Очистка при перезагрузке ОС                                             │  
│                                                                             │  
│  📌 Вывод:                                                                 │  
│  /dev/shm — это ВРЕМЕННОЕ хранилище.                                      │  
│  Задачи имеют смысл ТОЛЬКО в рамках текущей сессии бота.                  │  
│                                                                             │  
└─────────────────────────────────────────────────────────────────────────────┘  
```  
  
### 1.3. Почему выбран /dev/shm  
  
| Причина | Обоснование |  
|---------|-------------|  
| **Скорость** | Конвертация требует интенсивного чтения/записи временных файлов |  
| **Износ SD-карты** | На Raspberry Pi SD-карта — узкое место, постоянная запись сокращает её жизнь |  
| **Простота очистки** | При перезагрузке ОС всё очищается автоматически |  
| **Отказоустойчивость** | При падении бота данные в /dev/shm остаются (можно восстановить) |  
  
### 1.4. Стратегия очистки для /dev/shm  
  
```  
┌─────────────────────────────────────────────────────────────────────────────┐  
│                    СТРАТЕГИЯ ОЧИСТКИ ДЛЯ /dev/shm                          │  
├─────────────────────────────────────────────────────────────────────────────┤  
│                                                                             │  
│  1. При старте бота:                                                        │  
│     └── Полная очистка всех папок task_*                                   │  
│         (безопасно, т.к. /dev/shm — временное хранилище)                   │  
│                                                                             │  
│  2. В фоне (каждые 10 минут):                                               │  
│     └── Удаление папок старше 1 часа (по mtime)                            │  
│         (обновляется через touch_task при взаимодействии)                  │  
│                                                                             │  
│  3. После завершения задачи:                                                │  
│     └── Немедленное удаление папки                                          │  
│                                                                             │  
│  4. При ошибке:                                                             │  
│     └── Немедленное удаление папки (через finally)                         │  
│                                                                             │  
│  ⚡ Общее правило:                                                          │  
│  └── Папка живёт максимум 1 час                                            │  
│                                                                             │  
└─────────────────────────────────────────────────────────────────────────────┘  
```

## 4. Особенности для повышения отказоустойчивости  
  
### 4.1. Защита от дублирующих операций (TaskLockManager)  
  
```python  
class TaskLockManager:  
    """Предотвращает одновременный запуск конвертации и спеллера."""  
      
    async def acquire(self, task_id: str) -> bool:  
        # Атомарная проверка и захват  
        async with self._dict_lock:  
            if task_id in self._active:  
                return False  
            # ... захват блокировки ...  
            self._active.add(task_id)  
            return True  
      
    async def release(self, task_id: str):  
        # Безопасное освобождение  
        async with self._dict_lock:  
            self._active.discard(task_id)  
            # ... освобождение блокировки ...  
```  
  
**Почему это важно:**  
- Aiogram обрабатывает обновления конкурентно  
- Без блокировки возможны гонки (спеллер + конвертация)  
- Два `TaskContext` могут удалить папку одновременно  
  
---  
  
### 4.2. Безопасный контекстный менеджер (TaskContext)  
  
```python  
class TaskContext:  
    async def __aenter__(self):  
        # ✅ Проверки ДО захвата блокировки  
        self.session_data = sessions.get(self.task_id)  
        if not self.session_data:  
            raise ValueError("Session not found")  
          
        # ✅ Проверка файлов  
        if not self.task_dir.exists():  
            raise FileNotFoundError("Task directory not found")  
          
        # ✅ ТОЛЬКО ПОСЛЕ ВСЕХ ПРОВЕРОК — блокировка  
        if not await task_lock_manager.acquire(self.task_id):  
            raise RuntimeError("Task already processing")  
        self.lock_acquired = True  
          
        # ✅ Обновление активности  
        touch_task(self.task_dir)  
        return self  
      
    async def __aexit__(self, exc_type, exc_val, exc_tb):  
        # ✅ Гарантированное освобождение  
        if self.lock_acquired:  
            await task_lock_manager.release(self.task_id)  
          
        # ✅ Гарантированная очистка  
        sessions.pop(self.task_id, None)  
        safe_delete_task_dir(self.task_dir)  
```  
  
**Ключевые решения:**  
1. Проверки **ДО** блокировки — утечки невозможны  
2. `touch_task()` — активные задачи не удаляются  
3. `finally`-подобное поведение — гарантированная очистка  
  
---  
  
### 4.3. Асинхронная очистка (не блокирует бота)  
  
```python  
async def cleanup_loop(shm_dir: Path, interval: int = 600, max_age: int = 3600):  
    while True:  
        await asyncio.sleep(interval)  
        try:  
            # ✅ Запуск в отдельном потоке (не блокирует event loop)  
            await asyncio.to_thread(cleanup_old_tasks, shm_dir, max_age)  
        except Exception as e:  
            # ✅ Ошибка не прерывает цикл  
            logging.error(f"❌ Ошибка в cleanup_loop: {e}", exc_info=True)  
```  
  
**Почему это важно:**  
- `shutil.rmtree()` может быть медленным (много файлов)  
- В основном потоке это блокировало бы ответы бота  
- `asyncio.to_thread()` переносит работу в фоновый поток  
  
---  
  
### 4.4. touch_task() — защита от преждевременной очистки  
  
```python  
def touch_task(task_dir: Path):  
    """Обновляет mtime папки — сигнал, что задача жива."""  
    if task_dir and task_dir.exists():  
        try:  
            os.utime(task_dir, None)  # обновляет mtime  
        except Exception as e:  
            logging.error(f"Ошибка touch для {task_dir}: {e}")  
```  
  
**Где вызывается:**  
- После загрузки файла  
- При вводе диапазонов  
- При нажатии кнопок  
- При старте конвертации  
- В спеллере  
  
**Зачем:**  
- Очистка удаляет папки по `mtime`  
- Без обновления активная задача может быть удалена  
- Пользователь может долго вводить диапазоны  
  
---  
  
### 4.5. finally — гарантированная очистка ресурсов  
  
```python  
@router.message(F.document)  
async def handle_docs(...):  
    success = False  
    try:  
        # ... загрузка ...  
        success = True  
    except Exception as e:  
        # ... обработка ...  
        raise  
    finally:  
        # ✅ Всегда выполняется  
        if not success and task_id in sessions:  
            sessions.pop(task_id, None)  
        if not success:  
            safe_delete_task_dir(task_dir)  
```  
  
**Зачем:**  
- Любая ошибка должна очищать ресурсы  
- Нет утечек памяти в `/dev/shm`  
- Нет "осиротевших" сессий

## 5. Оптимизации для Raspberry Pi  
  
### 5.1. Ограничение одновременных конвертаций  
  
```python  
converter_semaphore = asyncio.Semaphore(2)  
```  
  
**Почему:**  
- Raspberry Pi имеет ограниченные ресурсы (CPU, RAM)  
- Конвертация PPTX → PNG ресурсоёмкая  
- 2 параллельные конвертации — оптимальный баланс  
  
### 5.2. Использование /dev/shm  
  
| Аспект | Решение |  
|--------|---------|  
| **Скорость** | RAM-диск ~ в 10 раз быстрее SD-карты |  
| **Износ** | SD-карта не страдает от частых записей |  
| **Очистка** | Автоматическая при перезагрузке |  
| **Размер** | Ограничен, но задачи временные (~1 час) |  
  
### 5.3. Логирование с ротацией  
  
```python  
info_handler = RotatingFileHandler(  
    os.path.join(log_dir, "bot.log"),  
    maxBytes=10 * 1024 * 1024,  # 10 МБ  
    backupCount=5  
)  
```  
  
**Почему:**  
- SD-карта не переполняется  
- Логи не занимают много места  
- Старые логи автоматически удаляются  
  
### 5.4. Асинхронная обработка  
  
| Компонент | Решение |  
|-----------|---------|  
| `asyncio.to_thread()` | Тяжёлые операции в фоновых потоках |  
| `await` везде | Нет блокировок event loop |  
| `asyncio.create_task()` | Фоновые задачи (очистка) |

## 6. Ключевые решения и их обоснование  
  
| Решение | Обоснование | Альтернатива |  
|---------|-------------|--------------|  
| **/dev/shm для временных файлов** | Скорость, износ SD-карты | SD-карта (медленно, износ) |  
| **Полная очистка при старте** | Безопасно для /dev/shm | Проверка PID (сложно) |  
| **Очистка по mtime** | Простота, надёжность | Проверка PID+UUID (сложно) |  
| **TaskLockManager** | Защита от гонок | Только семафор (недостаточно) |  
| **Проверки ДО блокировки** | Нет утечек блокировок | Проверки после (утечки) |  
| **touch_task()** | Активные задачи не удаляются | Фиксированный таймаут (риск) |  
| **asyncio.to_thread()** | Не блокирует бота | Синхронная очистка (блокировка) |  
| **finally блоки** | Гарантированная очистка | Только try/except (риск утечек) |

## 7. Безопасность  
  
| Аспект | Решение |  
|--------|---------|  
| **Доступ** | Админское одобрение новых пользователей |  
| **Валидация путей** | `validate_download_path()` — защита от path traversal |  
| **Владелец задачи** | `.owner` файл — проверка user_id и chat_id |  
| **Очистка** | Проверка `.owner` перед удалением папки |
